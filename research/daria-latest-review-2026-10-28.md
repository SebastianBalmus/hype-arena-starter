# Review: Daria round 4 (5943f61)

Reviewed `1cdb5b1..5943f61` against `EVALUATION.md`, the repository README/contracts, and `.agents/skills/hype-arena-evidence-policy/SKILL.md`. This is a read-only code review; the current checkout is on `bogdan`, so references below point to `5943f61`.

## Findings

1. **Potential false negative polarity from a clause-global negation scan (medium).** `negated_at` scans all negation words between clause start and clause end, regardless of whether the negation scopes the matched attribute (`hooly/extract.py:95-117`). Thus a sentence like “Hooly is not SOC 2 certified, but supports SSO” can flip a distinct positive Boolean attribute if its cue starts in the same punctuation-delimited clause. The colon branch correctly handles bare `no`, but its `yes` behavior is implicit and it does not distinguish negation scope. Add contrastive multi-Boolean examples and scope/coordination cases before trusting the reported 2/174 polarity errors.

2. **Later-page and prior-row context needs a sanitized-input audit (medium, protocol-sensitive).** Candidate subjects include all later page mentions (`hooly/reader.py:288-320`), while earlier page rows can contribute their parsed atoms (`:300-307`). Batch unlabelled text is permitted by `batch_unlabelled_v1`, so later *text* is allowed as an unlabelled cue; held-out labels/forms must never contribute to parser fitting, context atoms, or factual state. Confirm every split runner blanks test labels/forms before `Pipeline.fit` and that `parse_all` never carries evaluator gold atoms. The production path has intentional labelled practice evidence, consistent with the competition contract, but this alone does not establish clean retrospective benchmark access.

3. **Self-training has a failure mode if enabled, although default runtime leaves it off.** `_self_train` promotes any parsed row meeting `all(parse_cal(p) >= threshold)` into `train_rows + pseudo` (`hooly/pipeline.py:69-87`). `all([])` is true; if a parsed row has atoms but no `parse_scores`, it can be promoted vacuously. Guard for a non-empty score set and verify complete per-atom score coverage. The code path also trusts calibrated parse confidence as pseudo-label correctness, which is not an evidence proof; keep disabled unless a larger batch-access experiment supports it. The reported CV result is negative (0.880 vs 0.884 raw; `docs/EXPERIMENTS.md`, Round 4).

4. **Runtime expected-accuracy diagnostic is a model estimate, not a self-check against truth.** It averages the selected label confidence or unsure probability (`hooly/run.py:98-121`); on hidden rows it cannot measure realized accuracy. Name/report it as expected accuracy and avoid presenting the 0.881 vs 0.876 practice-shaped match as an independent runtime validation. Also ensure the `unsure` probability corresponds to actual emitted `unsure` after calibration/policy.

5. **Classifier feature additions are sensible but need targeted ablations.** Nested/partial/later subject sources and crude five-character stems enter scoring (`hooly/reader.py:97-105, 288-320, 360-445, 464-491`). Partial tokens can be polysemous and five-character stems collide; candidate ranking also gives every partial candidate the same `len(subs)` rank. Add error slices for collisions, nested-name ambiguities, repeated entity tokens, and same-page unrelated products. The reported round-4 benchmark is mixed (stratified 0.861 vs 0.868; temporal 0.834 vs 0.838; checker 0.874 vs 0.861), so the claim of overall improvement should remain limited to parser/CV gains and checker track, not generalized benchmark lift.

## Suggested experiments

- Contrastive Boolean polarity suite: two Boolean attributes in one sentence, conjunctions/disjunctions, “not only”, quoted negation, colon answers, and negation outside the attribute clause. Report per-attribute polarity confusion, not only aggregate accuracy.
- Re-run the new parser under frozen `evaluation/splits-v1.json` with gold test forms/labels inaccessible to the runner; preserve all three tracks and the `fixed_050` policy. Add per-feature ablations (`nested`, `partial`, `later`, `stem`) with paired row-level deltas.
- For page-context cues, compare prior-only, prior+later-text, and no-page-context using the same split and access profile. Explicitly test that test labels/forms are removed before fitting and that changing held-out gold forms cannot change predictions.
- Keep self-training off; if revisited, require nonempty complete scores and evaluate at runtime-shaped unlabelled batch sizes with a clean split-scoped audit.
- Report false recall/precision and unsure F1 alongside accuracy; round-4 accuracy remains high while unsure F1 is zero in the shown stratified result, and false recall is about 0.49.

## Daria adapter note

The outer split boundary in `integrations/daria_predict.py` is preserved: runtime rows must equal manifest train+test IDs, test labels are empty, and forms are supplied only for outer-train IDs. The inner `HybridStack.fit`/`FeatureHybrid.fit` OOF loops mask held-fold labels but retain their training forms (`hooly/hmm.py` at 5943f61; `experiments/daria_sklearn.py`). This is **not outer validation/test leakage**, because those IDs are permitted outer training rows. It does create training-feature optimism / a train-inference mismatch: `TimelineHMM.fit` treats held rows' retained atoms as free observations and `predict` scores with those same gold atoms, while deployment pending rows have no supplied forms and must be parsed from text. A clean comparison should clear held-fold atoms and parse held text with the fold's permitted fit rows, or describe the feature generator as gold-form-assisted OOF features rather than equivalent inference features.

For `integrations/daria_features.py`, the parse-calibration override fits a reader on `calibration_fit_ids`, clears labels/forms on the other outer-training rows for parse inference, and uses those held forms only to fit the isotonic parse-confidence map. It then calls the parent `Pipeline.fit` on all outer-training rows, refitting the reader/truth model with all forms. This is acceptable as an inner cross-fit for the `fixed_050` full-training lane, but it is not the `validation_5pct` lane described in `EVALUATION.md` §4, which forbids refitting on validation rows after calibration. The adapter now rejects out-of-vocabulary labels before source import and the shared CSV reader rejects short rows; subprocess coverage is in `tests/test_daria_features.py`.
